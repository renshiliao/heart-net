## C. 未修与新问题的正确改法（只登记，不代改）

1. **fuse 整行校验补齐** `[推断]`：让 fuse 与 sum/report/doctor 共用同一套 schema 与语义校验，明确 token 只能为 `0..999999999999999` 或成对 `-1`，并校验工具长度、日期、时区；任何非空坏行一律报实际行号并 `exit 3`，不能只数“结构不合规”。
2. **计量写失败判定修正** `[推断]`：不要用 `if ! (...) 9>>"$LOCKFILE"` 判断复合重定向；改为显式测试“打开锁文件、取得 flock、写数据文件”三个返回码，任一失败都退出 3，成功消息只能在确认数据行落盘后输出。
3. **circuit 坏状态先检后写** `[推断]`：`knock` 在追加前先完整校验 `$sig.knocks`，发现坏行立即报损且不改状态；追加、计数、熔断迁移应在同一 `flock` 临界区内完成，并检查 `.tripped/.scene/审计行` 的写入结果。
4. **doctor 行号出口去零** `[推断]`：账本每个坏行直接产生 `文件:行号:错误类别` 红项，或文件级汇总不使用“第 0 行”；不要再让错误的行号出现在主标签。
5. **账本 schema 统一防静默** `[推断]`：非法日期、非法时区、超长 `tool` 等应归入明确错误类别并退出 3，不能因为“不计入今日”就静默 `next`；建议只保留一个校验 awk 逻辑，五件套共同引用或逐字复制同一契约。

## D. 收尾总评

**总评：仍打回；五件主场景可用，但 fuse 伪账漏拦、写失败假报成功和坏状态被追加会继续破坏账目/状态完整性，须修后可发布。** `[亲验]`
