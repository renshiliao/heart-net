# 开源版保险机制复核报告

## A. 复核结论

**结论先行：五件均标 `[修正]`，当前版本 `[打回]`。** `[亲验]` 主链路里，计量汇总和日熔断在本机 `mawk 1.3.4` 下失效且熔断器按 0 token 放行；doctor 还能执行配置里的 shell 命令替换。虽然撞墙熔断、哨兵和 doctor 的指定主场景能跑通，但不足以抵消失败放行与命令执行风险。

证据口径：`[亲验]` 表示本次在 `./ins_test/` 实跑所得；`[推断]` 表示由代码路径推导、未把未复现情形写成实测数据。本次时间为 `2026-11-02T20:01:39+0000` 起，环境 awk 为 `mawk 1.3.4 20260302`；CC 记录写的是手机 Termux、GNU Awk 5.3.2，环境差异会进入对账结论。

### 1. 计量表 `usage_meter.sh + usage_report.sh` — `[修正]`

- `[亲验]` 三笔流水能追加，含一笔 `-1/-1`；但 `usage_report.sh day` 和 `usage_meter.sh sum` 在 mawk 下报 `match(..., a)` 语法错，日报伪报 0 且退出 0，`sum` 退出 2。`usage_report.sh:26`、`usage_meter.sh:56`、`fuse.sh:46` 使用了 GNU awk 扩展，与“纯 awk”说法不符。**正确说法**：仅在 GNU awk 可用时可称“同源同数”，或者改成 POSIX awk。**改法**：去掉 `match()` 第三参数，用 `match()+substr()` 解析；若保留 GNU awk 依赖，启动时显式检查并在缺失时退出非 0，日报不得吞掉聚合错误。
- `[亲验]` `--in -2 --out -2` 被接受，`--tool 'chat","injected":1'` 生成结构损坏的 JSON；这不符合“只收非负整数或 -1、只记数字不记内容”。`usage_meter.sh:38` 的正则允许任意负数，`usage_meter.sh:46` 未转义 tool。**正确说法**：token 只能是 `0..N` 或成对 `-1`；正文不落盘，tool 只能是受控标签。**改法**：改用 `^(-1|[0-9]+)$`，tool 做白名单或 JSON 转义，并明确“只记用量元数据，不记提示词/回答”。
- `[亲验]` `USAGE_DATA` 父目录不存在时，写入报错后仍输出“已记一笔”并退出 0。`usage_meter.sh:46` 失败未拦截，`usage_meter.sh:47` 仍报成功。**正确说法**：写失败必须显式失败。**改法**：预先创建并检查父目录，检查 `printf >>` 返回值，失败时不输出成功、直接退出非 0。
- `[亲验]` 100 路并发追加得到 100/100 合规行；但代码没有锁或原子写契约。`[推断]` tool 变长、不同文件系统或实现把一行拆成多次 write 时仍有交错风险。**改法**：用 `flock` 包住单行追加，或正式限定“短行、O_APPEND、Linux 文件系统”的原子边界。
- `[亲验]` 变量置顶、中文注释、用法示例、日期机械取时基本合格；七个脚本/配置都有 `Apache License 2.0` 人读头。`README.md` 所称“全文见 README”不实，README 没有 Apache-2.0 全文。**改法**：补 `LICENSE`/Apache-2.0 全文并修正指针，或把头改成准确的 SPDX 许可声明。

### 2. 日限额+熔断 `daily_limit.conf + fuse.sh` — `[修正]`

- `[亲验]` `DAILY_LIMIT=0` 与 `-1` 都拒绝，退出 3，边界判断正确。`fuse.sh:80` 的正整数校验可保留。
- `[亲验]` 按 40→90→120 灌数后，mawk 解析失败，五次 `gate` 全部显示“累计 0/100”并退出 0；没有出现应有的 0/2/1。`fuse.sh:46` 的 GNU awk 扩展失败后，`fuse.sh:51` 输出空结果，后续把空值当 0。**正确说法**：用量读取失败时必须失败拒绝，绝不能把未知当 0。**改法**：改 POSIX awk，检查 `today_total` 双值均为非负整数；任何聚合/状态写入错误退出 3 或 1，禁止放行。
- `[亲验]` 状态目录不可创建时，`fuse.sh:28` 只打印 mkdir 错误，随后仍放行。**改法**：`mkdir -p`、事件追加、tripped/warned 写入任一失败都立即拒绝 LLM 调用，并给独立的基础设施错误码。
- `[推断]` 80%/100% 阈值表达式本身覆盖 `>=80%`、`>=100%`，告警档每天只发声一次；但 `tripped`/`warned`/事件文件没有并发锁，重复告警、复位竞态仍可能。**改法**：状态迁移加锁并以临时文件原子替换。
- `[推断]` “次日自动复位”应表述为：清除昨日熔断状态后重新按今日累计判定；若今日仍已超限，会再次熔断。本次“只把熔断日改昨天、今日流水仍 120”的字面场景不能单独证明归零复位，CC 实测实际同时把流水也挪到了昨天。
- `[亲验]` README 接线 `bash fuse.sh gate || exit 1` 会把“80% 告警但放行”的退出 2 也拦掉，和 `README.md:52` 的注释冲突。**正确说法**：0/2 放行，1/3 拒绝。**改法**：显式接收返回码，例如仅在 `rc=1|3` 时退出，不能用裸 `|| exit 1`。

### 3. 脚本哨兵 `sentinel.sh` — `[修正]`

- `[亲验]` `./ins_review/` 基线后两遍同态输出去掉机械时间戳逐字一致；disk 水位 0 时真实告警，退出 1。主场景符合“三态、空闲单行 OK、有事才喊”。
- `[亲验]` 状态目录不可创建时，`sentinel.sh:34` 失败未停，`sentinel.sh:43` 快照写失败，却仍报“首次建档、快照已存”。**正确说法**：状态无法持久化就不能声称巡检成功。**改法**：检查目录、快照和 pos 写入，失败统一 `CRIT`、退出 2。
- `[亲验]` “确定性输出”只能准确说成“同一状态下，除 `date` 时间戳外输出固定”；首轮“首次建档”和后续“无变动”是不同状态，不能逐字等同。**改法**：把确定性契约和时间戳例外写清，测试固定先建基线再对拍两遍。
- `[推断]` `sentinel.sh:80` 只验整数，不拒绝 101% 等无效水位；`sentinel.sh:65` 仅在文件缩小时重扫，轮转替换为更大旧文件可能漏看。**改法**：水位限 0–100；日志状态同时记 inode，替换/轮转即从 0 重扫。
- `[推断]` `dir` 只哈希 `ls -la`，能看名字/大小/时间等目录条目状态，但不是文件内容哈希；“目录有变动”应限定为条目元数据变动，若要抓内容改写需逐文件摘要。

### 4. 撞墙熔断 `circuit.sh` — `[修正]`

- `[亲验]` 顺序 `check→knock×3→check→reset→check` 完整通过：第 3 次退出 1，`.scene` 非空且含现场标题/进程/磁盘/日志段，熔断后 check 和再次 knock 均拒绝，reset 后放行。
- `[亲验]` 20 路并发敲同一签名，最终计数只有 5 且已熔断，说明 `circuit.sh:52` 的读数与 `circuit.sh:53` 的写数发生丢失更新。**正确说法**：三次失败必须按三次失败计，不能按调度次数近似。**改法**：同一签名用 `flock` 串行“读-加-判-写”，或使用单条 append-only 失败流水后计数。
- `[亲验]` 计数文件写成 `bad` 时，`circuit.sh:53` 报“unbound variable”并退出 1，错误既不指向状态文件也不安全归类。**改法**：先验计数为非负十进制整数，损坏时明确报状态损坏并失败拒绝。
- `[亲验]` `CIRCUIT_DIR` 不可创建时，`circuit.sh:41` 失败但 `check` 仍返回“可跑”。**改法**：状态目录/状态写入失败必须拒跑，不能把“查不到熔断”当“未熔断”。
- `[亲验]` reset 只删除 `tripped/count`，人工复位时间只打印到 stdout；`circuit.sh:79` 与 `README.md:65` 所称“人工复位留痕”不一致。`ok` 对已熔断任务也只清 count，却提示成功，语义含混。**改法**：追加 append-only reset/ok 事件；已熔断时 `ok` 明确拒绝，或把清计数和解熔断拆开。

### 5. 防呆体检 `doctor.sh` — `[修正]`

- `[亲验]` 坏配置的字符串限额、坏路径、坏端口分别指到第 2/3/4 行，退出 1；原好配置全绿，退出 0；0 与负限额均红。指定主场景通过。
- `[亲验]` `CHECK_PORT=x$(touch ./ins_test/doctor_injection_proof):1` 令证明文件生成。`doctor.sh:88` 把配置拼进 `bash -c`，配置内容会执行 shell 命令替换。**正确说法**：doctor 只能检查配置，不能求值配置。**改法**：严格校验 host/port 后在当前 shell 受控重定向，或用 `nc`/Python socket 以 argv 传参；禁止 `bash -c` 拼接。
- `[亲验]` `DAILY_LIMIT=100` 但缺 `CHECK_PATH` 时出现黄项，`doctor.sh:117` 仍称“全绿、可以启动”，与“全绿才许启动”冲突。**正确说法**：有 WARN 就不是全绿。**改法**：要么把缺关键路径升红，要么让 `WARNINGS>0` 也退出 1，并把文案改成“无红项”。
- `[亲验]` 计量表坏行报成“第 0 行”，没有履行红项指行号。`doctor.sh:101` 只计坏行数。**改法**：输出每个坏行的实际行号和简短错误类别。
- `[亲验]` `doctor.sh:99` 在脚本中途定义 `USAGE_DATA`，不符合严格“变量置顶”；且相对路径以 cwd 为基准，而 `CHECK_PATH` 以配置目录为基准。**改法**：变量移到文件头，计量表相对路径统一以配置目录解析。
- `[亲验]` 端口只查数字形态，不约束 1–65535；IPv6 的 `host:port` 也解析不稳。**改法**：分别校验 host、端口区间，明确 IPv4/主机名/IPv6 格式。

### README 三层保险声明与设计纪律 — `[修正]`

- `[亲验]` 三层标题都在：①默认保护、②拆保险后果自负、③只对装保险时负责，三层边界总体讲得清楚。
- `[亲验]` ①“开箱即生效”不准确；实际必须把 gate/check/usage_meter 接进调用链，sentinel 必须挂 cron，doctor 必须被启动流程调用才生效。**正确说法**：按 README 接线后默认启用，未接线不构成保护。
- `[亲验]` ②“每一项拆保险动作都会在流水里留痕”过头：调大限额、不跑哨兵、绕过 doctor 均未留痕；circuit reset 只打印、不持久化。**正确说法**：当前只保证部分 fuse/circuit 事件留痕，或补齐全部审计后再作此声明。
- `[亲验]` ③责任边界本身清楚，但“doctor 全绿”与 doctor 实际“黄项不拦”冲突。**改法**：统一全绿定义后再保留该免责前提。

## C. 可回灌清单审读

评级口径：看“当前这套实现能否安全搬给老吴/老周”，不只评抽象想法。

1. **熔断只断花钱路** — `[存疑]` `[推断]` 架构方向正确，但当前 fuse 在非 GNU awk 下失败放行，README 还会把退出 2 误杀；修正计费失败语义和调用方返回码后才值得回灌。
2. **-1 不估数纪律** — `[可留档]` `[亲验]` 口径值得保留，现件却接受任意负数且 JSON 可被 tool 破坏；先修校验和 JSON 边界，再回灌账目流水。
3. **次日复位按日期比对** — `[值得回灌]` `[亲验]` 少依赖 cron 的思路简单可靠；回灌时补上“复位后仍按当日累计重判”的语义。
4. **哨兵三态确定性输出** — `[可留档]` `[亲验]` 输出契约好用，现件状态目录失败会假成功、轮转也有漏扫洞；契约可取，脚本需加固后回灌。
5. **doctor 红项指行号** — `[存疑]` `[亲验]` 指行号思路好，但现件存在配置触发命令执行，绝不能原样回灌；必须先改成纯数据校验。
6. **撞墙熔断现场落盘** — `[可留档]` `[亲验]` `.scene` 能显著缩短排障时间，现件并发丢计数且 reset 不持久留痕；修锁和审计后再回灌长跑任务入口。

## D. 收尾总评

**总评：打回；先消除 doctor 命令执行、熔断失败放行、状态写入假成功和并发丢计数，再复测 GNU awk/mawk 双环境，全部通过后方可发布。** `[亲验]`
