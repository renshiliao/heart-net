## B. 未修与新问题的正确改法（只登记，不代改）

1. **计量并发边界**：用 `flock` 包住单行追加，或在 README 明确只保证“短行、单一 `write`、`O_APPEND`、Linux 本地文件系统”的原子边界，不能只写 `append-only`。
2. **报表坏账处理**：`usage_meter.sh sum` 与 `usage_report.sh aggregate` 对每个非空行做完整结构、日期、整数范围和 `-1` 成对校验，任何坏行输出实际行号并以非 0 退出，禁止静默 `next`。
3. **fuse 严格账本解析**：整行必须匹配完整 JSONL schema，日期取完整字段，token 只能为 `0..N` 或成对 `-1`，字段子串命中不能代替整行解析，任何非空坏行一律退出 3。
4. **fuse 并发状态迁移**：同一状态目录用 `flock` 串行完成读判写，`tripped`、`warned_*`、事件行均检查返回值并原子落盘，确保告警事件每日至多一条。
5. **circuit 状态完整性**：只统计格式严格等于“机械时间戳 + `knock`”的行，发现其他内容立即报状态损坏并拒跑，不能把坏行计作失败次数。
6. **doctor 账本体检**：把“第 0 行”改成 `文件:行号:错误类别`，逐行报告；同时校验 `-1` 成对、整数范围和完整 JSON 结构，不能只做字段正则。
7. **doctor 端口契约**：若支持 IPv6，按 `[IPv6]:port` 明确解析并分别验 host/port；若不支持，则在 README 与报错中明示只支持 IPv4/主机名，避免把 IPv6 写成普通写法错误。
8. **README 留痕范围**：把普通敲墙明确写为 `$sig.knocks`，把熔断、成功清零、人工复位明确写为 `circuit_events.jsonl`，不要把两类落点混成同一审计文件。
